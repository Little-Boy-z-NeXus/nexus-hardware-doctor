# H01/H04 model adapter and diagnosis planner

The software exposes `await planner.plan(context, observations)` for both `MockPlanner` and `NebiusPlanner`. Constructing a provider does not call a service. The mock is a deterministic **rule-based simulation**, not a Nemotron model or proof of physical diagnosis. It ranks actual supplied readings and observations; evaluation labels and unknown input fields are excluded.

The plan contains hypotheses with confidence and evidence IDs, one proposed available tool or null, an overall confidence, a short user message, and a stop condition. Confidence values are heuristic estimates rather than calibrated probabilities. Plans reject unknown fields, duplicate IDs, nonfinite numbers, malformed JSON, unsupported tools/arguments, invented evidence references and inconsistent stop/tool combinations. Model output never executes a tool; policy and orchestration remain separate.

## Live configuration

Set these in the process environment or an ignored environment file loaded by the server:

- `NEXUS_NEBIUS_BASE_URL`: the account/model's HTTPS Nebius `/v1` base URL.
- `NEXUS_NEBIUS_API_KEY`: a private token stored locally or in a secret store, never in chat/Git.
- `NEXUS_NVIDIA_MODEL`: the exact available NVIDIA/Nemotron model ID for that endpoint.

There is no assumed model ID or credential. Copy endpoint/model values from the account's current model setup. Config accepts HTTPS Nebius domains only and rejects URL credentials, query strings and fragments. The API integration separately requires its explicit live-mode gate; consult the API guide before enabling billable calls. Nothing in the automated test suite enables a live provider or incurs API charges.

The transport uses non-streaming Chat Completions with a strict JSON-schema response format. It bounds input/output size, total attempt time, retries and backoff. It retries only transient connection/timeouts, rate limits and service errors. Authentication failures, refusal, truncated/malformed output and invalid plans fail closed with fixed public error codes. Redirects are disabled. Raw response bodies, hidden reasoning and request credentials never become diagnosis events. The configured key is rejected if echoed into model content or accidentally included in request data.

The versioned prompt treats symptoms, hardware names and observation content as untrusted data. Context is revalidated and projected into known fields. A schema and prompt cannot establish the factual correctness of model claims; referenced evidence still needs review, and deterministic safety rules remain authoritative.

## Simulated and physical observations

Observation dictionaries carry `evidence_id`, `status`, `source` and `data`. Supported facts include a canonical telemetry `sample`, reference current, driver output voltage, motor continuity, sensor timeout, and declared source/pin voltages. All measurements keep explicit `device`, `simulator` or `replay` provenance. Failed observations support only a `tool_error` hypothesis and a non-diagnosed stop. Software simulations do not establish motor motion, safe hardware ratings, physically repeated faults, or live model quality.

## Validation and remaining acceptance

Run `python -m pytest backend/tests/test_provider.py backend/tests/test_diagnosis.py -q`. Network tests use `httpx.MockTransport`; they cover malformed responses, refusal, rate limits, timeout, secret rejection, grounded evidence, prompt data isolation and hypothesis updates.

The successful real runtime calls, diagnosis results and remaining physical gates are recorded in the [live acceptance evidence](evidence/h01-h04-live-nebius.md). Preserve redacted provider/model identity, prompt version, schema-validation outcomes and supported hypotheses for subsequent runs. Do not commit raw prompts/responses or credentials. Offline mock evaluations do not substitute for real Nemotron measurements.

## Verified live profile — 12 September 2026

The [live acceptance record](evidence/h01-h04-live-nebius.md) documents successful runtime
requests. NVIDIA Nemotron Ultra returned ten valid diagnoses on the
current INA226 synthetic cases, and the live planner completed a read-only tool cycle.
Use this tested profile with your own locally saved key:

```dotenv
NEXUS_NEBIUS_BASE_URL=https://api.tokenfactory.nebius.com/v1
NEXUS_NVIDIA_MODEL=nvidia/Nemotron-3-Ultra-550b-a55b
NEXUS_NEBIUS_ENABLE_THINKING=true
NEXUS_NEBIUS_MAX_OUTPUT_TOKENS=4096
NEXUS_ENABLE_LIVE_MODEL=true
```

`diagnosis-v2` provides the schema in the prompt and limits generation to known evidence,
shared fault IDs and available tools. The wire schema omits Nebius's unsupported
`uniqueItems` keyword; local validation still enforces it. The full per-run schema is also
validated locally. One bounded correction is allowed for invalid content without replaying
raw output or private reasoning. The caller's overall deadline remains authoritative.
`enable_thinking` is optional for other models; output budget accepts 256–8192 tokens.
Do not infer that all catalog models work equally well from OpenAI API compatibility.
